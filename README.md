# החתמת ציוד — מערכת מוצפנת מקצה לקצה

מערכת רישום ומעקב ציוד אישי ליחידה: קישור אחד לכל החיילים, אישור ומעקב למנהל.
כל הפרטים האישיים (שם, מספר אישי, טלפון) מוצפנים **בדפדפן** לפני השליחה — השרת,
קלאודפלייר, וכל מי שמשיג גישה לחשבון או למסד הנתונים רואים צופן בלבד.

- **חייל:** פותח את הקישור ובוחר מבין שתי כרטיסיות — **החתמת ציוד** (פרטים, מחלקה,
  מספר נשק ורישיונות → בחירת ציוד עם כמות לכל פריט) או **בקשת ציוד / דיווח חוסר**.
- **מנהל:** נכנס דרך "כניסת מנהל" → מאשר הגשות → עוקב אחרי ציוד בחוץ → מזכה החזרות (גם חלקיות) → מנהל מלאי → סיכום וייצוא CSV.

> **אזהרה חשובה:** אין שחזור סיסמה. איבוד סיסמת המנהל = איבוד כל הנתונים.
> שמרו את הסיסמה במנהל סיסמאות או בכספת פיזית.

## פריסה (Cloudflare Pages + D1)

### דרישות מקדימות

```bash
npm install -g wrangler
wrangler login
```

### 1. דחיפה ל-GitHub

```bash
git init
git add .
git commit -m "Equipment sign-out system"
git branch -M main
git remote add origin git@github.com:USERNAME/tzayad.git
git push -u origin main
```

השתמשו ברפוזיטורי **פרטי**. אין סודות בקוד, אבל אין סיבה לפרסם אותו.

### 2. יצירת מסד נתונים ופריסה

```bash
wrangler d1 create tzayad
# העתיקו את ה-database_id שהוחזר אל wrangler.toml
wrangler d1 execute tzayad --remote --file=./schema.sql
git commit -am "Add D1 database id" && git push
```

בלוח הבקרה של Cloudflare → **Workers & Pages → Create → Pages → Connect to Git**:

| הגדרה | ערך |
|---|---|
| Framework preset | None |
| Build command | *(ריק)* |
| Build output directory | `public` |

לאחר מכן **Settings → Bindings → Add → D1 database**: משתנה `DB`, מסד `tzayad`,
גם ל-Production וגם ל-Preview. בצעו Redeploy כדי שהקישור ייכנס לתוקף.

### 3. הפעלה ראשונה — לפני שיתוף הקישור!

1. פתחו את כתובת הפריסה.
2. **כניסת מנהל** → בחרו סיסמה של 10+ תווים → אשרו שאין שחזור.
3. שמרו את הסיסמה במקום בטוח.
4. אופציונלי: הגדירו `SETUP_TOKEN` במשתני הסביבה של הפרויקט **לפני** הפריסה הראשונה,
   כדי שההקמה תדרוש כותרת `X-Setup-Token` (חוסם השתלטות על ההקמה).
5. אופציונלי: חברו דומיין מותאם תחת **Custom domains** — קישור קצר שורד טוב יותר בוואטסאפ.

מי שמשלים את ההקמה ראשון הופך למנהל — לכן יש לבצע את שלב 2 מיד אחרי הפריסה.

## פיתוח מקומי

```bash
npm install
npm run db:init:local
npm run dev          # http://localhost:8788
```

`npm run deploy` מריץ את הבדיקות לפני ההפצה ונעצר אם משהו נכשל. ההפצה יוצאת
מהמחשב ולא מגיטהאב, כי הפרויקט ב-Cloudflare נוצר כ-direct upload ואי אפשר
להמיר אותו לפרויקט מחובר-Git בלי ליצור פרויקט חדש — כלומר כתובת חדשה, וה-QR
של החיילים מצביע על הקיימת.

### קונסולת בדיקה עם נתונים

הקונסולה נעולה מאחורי סיסמה, ובלי סיסמה אי אפשר ללחוץ על כלום — כלומר אי
אפשר לבדוק. `npm run dev:seed` מקים קונסולה שנייה: מסד מקומי, מנהל זמני
שהסיסמה שלו מודפסת במסך, ונתונים מלאכותיים בכל מסך — חיילים ממתינים
ומאושרים, ארמון, מחסן קשר, תחמושת, רכבים, כרטיסי תדלוק, דיווחים, רשומה בסל
המיחזור ומשתמש עורך.

```bash
npm run dev            # בטרמינל אחד
npm run dev:seed       # בשני
```

הסקריפט מוחק את מה שהוא מוצא במסד המקומי ומתחיל מחדש, ולכן הוא **מסרב לרוץ
מול כתובת שאינה localhost**. הנתונים מומצאים: מספרים אישיים מ-8000000 ומעלה
וטלפונים מהחסימה 050-000, שאינם קיימים במציאות. הסיסמה מודפסת בכוונה — היא
לא מגינה על שום דבר.

## גיבוי

יצוא מלא של מסד הנתונים רץ **כל יום ב-21:00** דרך launchd, ונשמרים 14
העותקים האחרונים:

```bash
npm run db:backup        # גיבוי עכשיו, ידנית
npm run backup:install   # התקנה מחדש של המשימה המתוזמנת (אחרי עריכת הסקריפט)
launchctl unload -w ~/Library/LaunchAgents/com.tzayad.backup.plist   # לעצור
```

הקבצים יושבים ב-`~/Library/Application Support/Tzayad/backups`, ומופיעים גם
כ-`~/Downloads/Tzayad(30.7)/auto` דרך קישור סמלי. הם לא נמצאים ישירות
ב-Downloads מפני ש-macOS חוסמת גישה של משימה מתוזמנת לתיקיות Downloads,
Documents ו-Desktop אלא אם נותנים ל-`/bin/bash` גישה מלאה לדיסק — ויתור רחב
מדי בשביל גיבוי.

הסקריפט לא מוחק גיבוי קיים על סמך יצוא שנכשל: הקובץ יורד לשם זמני, נבדק
שהוא גדול מספיק ושהטבלאות שאמורות להיות בו נמצאות, ורק אז מחליף. **קובץ
הגיבוי מכיל את המפתח הפרטי העטוף — הוא נשאר על המחשב הזה.**

## תפעול

- **במהלך החתמה:** שולחים את הקישור לקבוצה וכל חייל נרשם מהמכשיר שלו.
  המנהל משאיר את לשונית "ממתין לאישור" פתוחה ומאשר במנות; **רענון** מושך הגשות חדשות.
- **השלמת ציוד:** חייל שהרישום שלו כבר אושר יכול להיכנס שוב ולסמן רק את הציוד
  הנוסף שקיבל. ההשלמה מופיעה אצל המנהל עם תג "השלמה", ובאישור היא מתמזגת
  אוטומטית לתוך הרישום הקיים של החייל (בלי רשומה כפולה).
- **הודעת אישור לחייל:** אחרי האישור הכרטיס מסמן **"הודעת רישום טרם נשלחה"**,
  וכפתור **וואטסאפ** במעקב ציוד פותח צ'אט עם החייל והודעה מוכנה מראש — נשאר רק
  ללחוץ שליחה, והכרטיס מסומן **"✓ הודעה נשלחה"**. ההודעה יוצאת מהמכשיר של
  המנהל, לא משרת, ולכן אף פרט אינו עובר לצד שלישי. מספרי טלפון מומרים
  אוטומטית לפורמט בינלאומי (05X… → 9725X…).
- **חיפוש בכל רשימה:** לכל רשימה בפאנל יש חיפוש משלה —
  **ממתין לאישור** ו**מעקב ציוד** (שם / מספר אישי / טלפון, עם צ'יפים לסינון מחלקה),
  **בקשות חוסר** (שם או תוכן הבקשה), **מלאי** (שם פריט, מופיע מ-5 פריטים ומעלה),
  ו**דוחות** — שם חיפוש אחד בראש הלשונית חל על שלוש הטבלאות שמתחתיו. הרשומות מקובצות
  למקטעים מתקפלים לפי מחלקה, עם מונה חיילים וכמה מהם עם ציוד בחוץ — כך הרשימה
  נשארת נוחה גם ב-100+ חיילים. חיפוש או סינון פותחים את המקטעים אוטומטית.
- **החזרות:** "מעקב ציוד" → סינון **ציוד בחוץ** → מציאת החייל → זיכוי פריט-פריט
  (למשל ספירת מחסניות) או **זיכוי מלא** כשהכול חוזר יחד. אחרי זיכוי מופיע כפתור
  **הודעת זיכוי** ששולח לחייל אישור וואטסאפ עם מה שהוחזר ומה שעדיין רשום עליו.
- **נשק ורישיונות:** בטופס הקליטה החייל ממלא **מספר סידורי של הנשק** (רשות), ומסמן
  אם יש לו רישיון נהיגה בתוקף. **ברישיון האזרחי** הסימון פותח **מספר רישיון,
  תאריך תוקף וגם צילום** — כך שהמנהל יכול גם לעקוב אחרי פקיעות וגם לראות את
  המסמך. **ברישיון הצבאי** יש צילום בלבד. בשניהם אפשר לצלם או לבחור מהגלריה; התמונה מכווצת במכשיר (עד ~280KB, הטקסט
  נשאר קריא), מוצפנת שם ונשמרת בטבלה נפרדת כדי שרשימת החיילים לא תוריד תמונות.
  כפתור **הצגת צילום** מפענח אותה רק כשלוחצים. מחיקת רשומה מוחקת גם את הצילומים.
- **מעקב רישיונות:** בלשונית **דוחות** יש טבלה של כל החיילים עם מספר הרישיון,
  תאריך התוקף, סטטוס וכפתור לצפייה בצילום. **פג תוקף / אין רישיון / ללא תאריך —
  שורה אדומה**, ורישיון שפג בתוך 60 יום מסומן ככתום. הטבלה ממוינת מהחמור לקל,
  ויש ייצוא CSV. בסקירה יש אריח נפרד לרישיונות, בנפרד מאריח הנשקים.
- **סקירה:** לשונית הפתיחה של הפאנל — אריחי מדדים (חיילים, פריטים בחוץ, אחוז
  החזרה, פריטים בחוסר, דיווחים פתוחים, נשקים), פילוח לפי מחלקה ופילוח ניצולת
  לפי פריט. הצבעים נבחרו ואומתו לנגישות (כולל עיוורון צבעים), וכל מצב נושא גם
  תווית או סימן — הצבע לעולם אינו הסימן היחיד.
- **בקשות ודיווחי חוסר:** דף נפרד בכתובת `#report`, **מנותק לחלוטין ממאגר
  ההחתמות** — החייל ממלא רק **שם וטקסט חופשי**, בלי מספר אישי ובלי מחלקה.
  אצל המנהל יש לשונית **חוסרים** עם מונה דיווחים פתוחים, סינון פתוחים/טופלו/הכל,
  כפתור **✓ סימון כטופל** (הפיך), קישור וואטסאפ ישיר לחייל ומחיקה.
- **רשימת נשקים:** בלשונית **סיכום** — טבלה של מספר סידורי מול מחזיק הנשק, שם,
  מ״א, מחלקה וטלפון, ממוינת לפי מספר, עם ייצוא CSV נפרד.
- **מי חתום על מה:** בלשונית **סיכום** יש טבלת ניהול — שורה לכל חייל, עמודה לכל
  פריט, והמספר הוא כמה עדיין אצלו מתוך מה שהוחתם (`2/3`), עם ✓ למה שהוחזר
  במלואו. הטבלה מציגה גם מספר אישי, מחלקה ומספר נשק, ומכבדת את החיפוש והסינון.
- **חוסרים:** טבלת הסיכום מציגה **מלאי פתיחה · הונפק · הוחזר · בחוץ · במחסן**.
  פריט שהוחתם מעבר למלאי הפתיחה מסומן בשורה אדומה, ומעליה באנר שמסכם את החוסר.
- **מלאי:** לשונית **מלאי** — הזינו כמה קיבלתם מכל פריט ביום קליטת הציוד,
  והמערכת מחשבת **פתיחה − אצל החיילים = נותר במחסן** מתוך ההחתמות המאושרות.
  אפשר להוסיף **פריטים נוספים** שהחיילים לא חותמים עליהם (מזרנים, אוהלים) עם
  ספירה ידנית, ולנהל **הערות בטקסט חופשי**. יתרה שלילית מסומנת באדום. הכול
  נשמר מוצפן, בדיוק כמו הרשומות — לחצו **שמירת המלאי** אחרי שינוי.
- **החלפת סיסמה:** בלשונית "אבטחה". מיידית, לא מצפינה מחדש רשומות, ומנתקת את כל החיבורים.
- **ייצוא:** לכל טבלה יש ייצוא CSV משלה (רישיונות, נשקים, מי-חתום-על-מה, וייצוא
  מלא). הקבצים נכתבים עם BOM ו-CRLF כך שעברית נפתחת נכון באקסל.
- **דו״ח צלם / צלם ארמון:** שתי לשוניות נפרדות, אותה שיטת עבודה. מוסיפים פריט
  עם **שם, מספר סידורי, תקן והערה**, ובכל ספירה יומית מזינים כמה **נספר בפועל**.
  ההפרש מחושב אוטומטית: **חוסר מסומן בשורה אדומה**, עודף בכתום, ומעל הטבלה
  אריחי סיכום (סה״כ תקן, סה״כ נספר, חוסר, עודף). יש **חיפוש לפי שם או מספר
  סידורי**, כפתור **סימון ספירה יומית** ששומר את התאריך, ו**ייצוא CSV** שכולל את
  תאריך הספירה ועמודת סטטוס במילים (חוסר/עודף/תקין). מונה החוסר מופיע כתג אדום
  על הלשונית. הנתונים נשמרים מוצפנים ב-vault כמו שאר המלאי.
- **עמודים:** כל רשימה בפאנל מוצגת ב-25 שורות לעמוד עם ניווט עמודים, כך שגם
  1000 חיילים לא מייצרים גלילה אינסופית. שינוי חיפוש או סינון מאפס לעמוד הראשון.
- **סוף תרגיל:** ייצאו CSV אם נדרש תיעוד (הקובץ **אינו מוצפן** — טפלו בו בהתאם לכללי
  היחידה), ואז **מחיקת כל הנתונים** בלשונית "אבטחה".

## הודעות לחיילים

ההודעות נשלחות **ידנית בלחיצה**: כפתורי הוואטסאפ בפאנל פותחים צ׳אט מהמכשיר
שלכם עם הודעה מוכנה מראש — פירוט הציוד שהוחתם, או מה שהוחזר בהודעת זיכוי.
שום שרת אינו מעורב, ולכן שם החייל, הטלפון ופירוט הציוד לא עוברים לאף צד שלישי.

הייתה כאן גם שליחה אוטומטית דרך WhatsApp Cloud API של Meta, והיא **הוסרה**.
היא דרשה רישום עסקי מול Meta שהיחידה אינה יכולה להשלים, ולכן לא שלחה הודעה
מעולם — כל אישור בזבז קריאת רשת כדי לקבל `not_configured`. בדרך היא גם הייתה
המקום היחיד שבו שם, טלפון ורשימת ציוד יצאו מהדפדפן בטקסט גלוי. בלעדיה לא
יוצא מהמערכת שום מידע קריא, לאף גורם.

## אבטחה — הערה חשובה למי שמתחזק את הקוד

**כל נתון מפוענח הוא קלט לא-מהימן.** המפתח הציבורי חשוף בכוונה — זה מה שמאפשר
לחייל להגיש בלי חשבון — ולכן *כל אחד* יכול להצפין מטען שרירותי ולשלוח אותו.
רשומה מפוענחת אינה "המידע שלנו"; היא קלט של תוקף פוטנציאלי.

לכן כל מטען עובר דרך `cleanRecord` / `cleanReport` / `cleanInv` ב-`app.js` לפני
שהוא נוגע ב-DOM: מחרוזות נחתכות באורך, מספרים נאכפים כמספרים סופיים, ומזהי
פריט ומחלקה עוברים רשימת היתר. **אם מוסיפים שדה חדש למטען — חייבים להוסיף אותו
גם לסניטייזר**, אחרת הוא זורם ל-`innerHTML` בקונסולת המנהל, במקום שבו המפתח
הפרטי נמצא בזיכרון.

## מה השרת כן רואה

מספר רשומות, סטטוס (ממתין/מאושר) וחותמות זמן — ללא זהות וללא פירוט ציוד.
