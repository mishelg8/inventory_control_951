# החתמת ציוד — מערכת מוצפנת מקצה לקצה

מערכת רישום ומעקב ציוד אישי ליחידה: קישור אחד לכל החיילים, אישור ומעקב למנהל.
כל הפרטים האישיים (שם, מספר אישי, טלפון) מוצפנים **בדפדפן** לפני השליחה — השרת,
קלאודפלייר, וכל מי שמשיג גישה לחשבון או למסד הנתונים רואים צופן בלבד.

- **חייל:** פותח את הקישור → פרטים, מחלקה, מספר נשק ורישיונות נהיגה → בחירת ציוד עם **כמות לכל פריט** → שליחה. פחות מדקה.
- **מנהל:** נכנס דרך "כניסת מנהל" → מאשר הגשות → עוקב אחרי ציוד בחוץ → מזכה החזרות (גם חלקיות) → מנהל מלאי → סיכום וייצוא CSV.

> **אזהרה חשובה:** אין שחזור סיסמה. איבוד סיסמת המנהל = איבוד כל הנתונים.
> שמרו את הסיסמה במנהל סיסמאות או בכספת פיזית.

## פריסה (Cloudflare Pages + D1)

### דרישות מקדימות

```bash
npm install -g wrangler
wrangler login
```

### 1. דחיפה ל-GitHub

```bash
git init
git add .
git commit -m "Equipment sign-out system"
git branch -M main
git remote add origin git@github.com:USERNAME/tzayad.git
git push -u origin main
```

השתמשו ברפוזיטורי **פרטי**. אין סודות בקוד, אבל אין סיבה לפרסם אותו.

### 2. יצירת מסד נתונים ופריסה

```bash
wrangler d1 create tzayad
# העתיקו את ה-database_id שהוחזר אל wrangler.toml
wrangler d1 execute tzayad --remote --file=./schema.sql
git commit -am "Add D1 database id" && git push
```

בלוח הבקרה של Cloudflare → **Workers & Pages → Create → Pages → Connect to Git**:

| הגדרה | ערך |
|---|---|
| Framework preset | None |
| Build command | *(ריק)* |
| Build output directory | `public` |

לאחר מכן **Settings → Bindings → Add → D1 database**: משתנה `DB`, מסד `tzayad`,
גם ל-Production וגם ל-Preview. בצעו Redeploy כדי שהקישור ייכנס לתוקף.

### 3. הפעלה ראשונה — לפני שיתוף הקישור!

1. פתחו את כתובת הפריסה.
2. **כניסת מנהל** → בחרו סיסמה של 10+ תווים → אשרו שאין שחזור.
3. שמרו את הסיסמה במקום בטוח.
4. אופציונלי: הגדירו `SETUP_TOKEN` במשתני הסביבה של הפרויקט **לפני** הפריסה הראשונה,
   כדי שההקמה תדרוש כותרת `X-Setup-Token` (חוסם השתלטות על ההקמה).
5. אופציונלי: חברו דומיין מותאם תחת **Custom domains** — קישור קצר שורד טוב יותר בוואטסאפ.

מי שמשלים את ההקמה ראשון הופך למנהל — לכן יש לבצע את שלב 2 מיד אחרי הפריסה.

## תפעול

- **במהלך החתמה:** שולחים את הקישור לקבוצה וכל חייל נרשם מהמכשיר שלו.
  המנהל משאיר את לשונית "ממתין לאישור" פתוחה ומאשר במנות; **רענון** מושך הגשות חדשות.
- **השלמת ציוד:** חייל שהרישום שלו כבר אושר יכול להיכנס שוב ולסמן רק את הציוד
  הנוסף שקיבל. ההשלמה מופיעה אצל המנהל עם תג "השלמה", ובאישור היא מתמזגת
  אוטומטית לתוך הרישום הקיים של החייל (בלי רשומה כפולה).
- **הודעת אישור לחייל:** ברגע שהמנהל לוחץ "אישור", המערכת מנסה לשלוח לחייל
  הודעת וואטסאפ אוטומטית ממספר ייעודי (ראו "שליחה אוטומטית" למטה). אם השליחה
  האוטומטית לא מוגדרת או נכשלה, הכרטיס מסמן **"הודעה טרם נשלחה"** ואפשר לשלוח
  ידנית בכפתור **שליחה בוואטסאפ** — הוא פותח צ'אט עם החייל והודעה מוכנה מראש,
  ונשאר רק ללחוץ שליחה. כרטיס שההודעה בו נשלחה מסומן **"✓ הודעה נשלחה"**.
  מספרי טלפון מומרים אוטומטית לפורמט בינלאומי (05X… → 9725X…).
- **חיפוש וארגון:** בלשוניות "ממתין לאישור" ו"מעקב ציוד" יש שדה חיפוש חופשי
  (**שם, מספר אישי או טלפון**) וצ'יפים לסינון לפי מחלקה. הרשומות מקובצות
  למקטעים מתקפלים לפי מחלקה, עם מונה חיילים וכמה מהם עם ציוד בחוץ — כך הרשימה
  נשארת נוחה גם ב-100+ חיילים. חיפוש או סינון פותחים את המקטעים אוטומטית.
- **החזרות:** "מעקב ציוד" → סינון **ציוד בחוץ** → מציאת החייל → זיכוי פריט-פריט
  (למשל ספירת מחסניות) או **זיכוי מלא** כשהכול חוזר יחד. אחרי זיכוי מופיע כפתור
  **הודעת זיכוי** ששולח לחייל אישור וואטסאפ עם מה שהוחזר ומה שעדיין רשום עליו.
- **נשק ורישיונות:** בטופס הקליטה החייל ממלא **מספר סידורי של הנשק** (רשות), ומסמן
  אם יש לו **רישיון נהיגה אזרחי/צבאי בתוקף**. סימון פותח אפשרות לצרף צילום של
  הרישיון — **מהמצלמה או מהגלריה**. התמונה מכווצת במכשיר (עד ~280KB, הטקסט נשאר
  קריא), מוצפנת שם, ונשמרת בטבלה נפרדת כדי שרשימת החיילים לא תוריד תמונות.
  אצל המנהל מופיע צ׳יפ ירוק לכל רישיון, וכפתור **הצגת צילום** שמפענח את התמונה
  רק כשלוחצים עליו. מחיקת רשומה מוחקת גם את הצילומים שלה.
- **מי חתום על מה:** בלשונית **סיכום** יש טבלת ניהול — שורה לכל חייל, עמודה לכל
  פריט, והמספר הוא כמה עדיין אצלו מתוך מה שהוחתם (`2/3`), עם ✓ למה שהוחזר
  במלואו. הטבלה מציגה גם מספר אישי, מחלקה ומספר נשק, ומכבדת את החיפוש והסינון.
- **חוסרים:** טבלת הסיכום מציגה **מלאי פתיחה · הונפק · הוחזר · בחוץ · במחסן**.
  פריט שהוחתם מעבר למלאי הפתיחה מסומן בשורה אדומה, ומעליה באנר שמסכם את החוסר.
- **מלאי:** לשונית **מלאי** — הזינו כמה קיבלתם מכל פריט ביום קליטת הציוד,
  והמערכת מחשבת **פתיחה − אצל החיילים = נותר במחסן** מתוך ההחתמות המאושרות.
  אפשר להוסיף **פריטים נוספים** שהחיילים לא חותמים עליהם (מזרנים, אוהלים) עם
  ספירה ידנית, ולנהל **הערות בטקסט חופשי**. יתרה שלילית מסומנת באדום. הכול
  נשמר מוצפן, בדיוק כמו הרשומות — לחצו **שמירת המלאי** אחרי שינוי.
- **החלפת סיסמה:** בלשונית "אבטחה". מיידית, לא מצפינה מחדש רשומות, ומנתקת את כל החיבורים.
- **סוף תרגיל:** ייצאו CSV אם נדרש תיעוד (הקובץ **אינו מוצפן** — טפלו בו בהתאם לכללי
  היחידה), ואז **מחיקת כל הנתונים** בלשונית "אבטחה".

## שליחה אוטומטית בוואטסאפ (אופציונלי)

ברירת המחדל היא שליחה ידנית בלחיצה. כדי שההודעה תצא **אוטומטית ממספר ייעודי**
ברגע האישור, צריך לחבר את המערכת ל-WhatsApp Cloud API של Meta.

> **לפני שמתחילים — המחיר של האוטומציה:** שליחה אוטומטית מחייבת שהשרת יקבל את
> מספר הטלפון, השם ופירוט הציוד בטקסט גלוי, ויעביר אותם ל-Meta. זו סטייה
> מההבטחה שכל המערכת נבנתה סביבה. הקוד ממזער את הנזק — שום דבר מזה **לא נכתב
> למסד הנתונים ולא נרשם ללוגים**, והוא קיים רק בזיכרון ה-Worker למשך הבקשה —
> אבל **Meta מקבלת עותק ושומרת אותו**. אם זה לא מקובל, השאירו את המערכת בשליחה
> הידנית: היא לא מדליפת דבר לאף גורם מלבד חברת הסלולר, שרואה כל הודעה ממילא.

### מה צריך להשיג מ-Meta

1. **חשבון Meta Business מאומת** (Business Verification) — דורש מסמכי התאגדות
   של גוף משפטי. זהו החסם המשמעותי ביותר; כדאי לבדוק אותו לפני כל השאר.
2. **מספר טלפון ייעודי** שאינו רשום כרגע בוואטסאפ רגיל או ב-WhatsApp Business.
   לאחר החיבור ל-API לא ניתן להשתמש בו באפליקציה הרגילה.
3. **תבנית הודעה מאושרת** (Message Template) — כיוון שהחייל לא פתח את השיחה,
   כל הודעה חייבת לצאת בתבנית שאושרה מראש. הגישו תבנית בקטגוריה **Utility**,
   בשפה **עברית (he)**, בשם `equipment_approved`, עם הגוף:

   ```
   שלום {{1}}, רישום הציוד שלך אושר והוחתמת על: {{2}}. נא לשמור הודעה זו לצורך החזרת הציוד.
   ```

   `{{1}}` = שם החייל, `{{2}}` = רשימת הציוד. האישור נמשך בדרך כלל דקות עד שעות.
4. **Access Token** ו-**Phone Number ID** מלוח הבקרה של האפליקציה.

### הגדרה ב-Cloudflare

בלוח הבקרה: **Workers & Pages → tzayad → Settings → Variables and Secrets**,
והוסיפו כ-**Secret** (לא כ-plaintext) לסביבת Production:

| משתנה | ערך |
|---|---|
| `WHATSAPP_TOKEN` | ה-Access Token מ-Meta |
| `WHATSAPP_PHONE_ID` | ה-Phone Number ID |
| `WHATSAPP_TEMPLATE` | *(רשות)* שם תבנית אחר, ברירת מחדל `equipment_approved` |
| `WHATSAPP_LANG` | *(רשות)* קוד שפה, ברירת מחדל `he` |

לאחר ההוספה בצעו Redeploy. **בלי המשתנים האלה המערכת פשוט נשארת בשליחה הידנית**
— אין שגיאה ואין צורך בשינוי קוד.

עלות: תבניות Utility בישראל עולות אגורות בודדות להודעה — עבור ~90 חיילים מדובר
בשקלים בודדים.

### חלופה: SMS במקום וואטסאפ

אם האימות העסקי מול Meta מסתבך, שליחת SMS אוטומטית דרך ספק ישראלי היא בדרך כלל
תהליך קל יותר (בלי אישור תבניות), והנתונים מגיעים לספק ישראלי במקום ל-Meta.
המבנה בקוד זהה — צריך רק להחליף את גוף הקריאה ב-`/api/admin/notify`.

## מה השרת כן רואה

מספר רשומות, סטטוס (ממתין/מאושר) וחותמות זמן — ללא זהות וללא פירוט ציוד.
היוצא מן הכלל היחיד: אם הופעלה שליחה אוטומטית, שם החייל, הטלפון ופירוט הציוד
עוברים דרך ה-Worker בזמן האישור ומגיעים ל-Meta. הם אינם נשמרים במסד הנתונים.
פירוט מלא של מודל האבטחה ותכנון ההצפנה נמצא ב-PLAN.md (אנגלית).
