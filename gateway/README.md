# שער WhatsApp — מסייעת 951

שירות Node.js נפרד ששולח הודעות WhatsApp דרך WhatsApp Web (התקנים מקושרים),
לא דרך Meta Cloud API. הוא רץ על שרת מתמיד — לא על Cloudflare — כי הוא מחזיק
דפדפן וסשן חי.

> **מצב: מוכן. חסר רק מספר טלפון.**
> הקוד שלם, נבנה, נבדק ורץ. מה שאין הוא קו שסרק את ה-QR. ברגע שיש מספר —
> `docker compose up -d`, לוחצים "חיבור" בקונסולה, סורקים, וזה עובד.

---

## ההחלטה הארכיטקטונית — התקבלה

**נבחר: להמשיך, עם הקלה מוגבלת להודעות יוצאות בלבד.** הדפדפן מפענח ומחבר,
ה-Worker מאמת שזה מנהל וחותם HMAC ומעביר בלי לאחסן, השער שולח. הכספת נשארת
אטומה לשרת; מה שנחשף הוא טקסט ההודעה ומספר הנמען, ורק ברגע השליחה.

מה שזה חייב במימוש — וכך נעשה:

- ה-Worker **אינו כותב לשום מקום** את גוף ההודעה או את הטלפון — לא ל-D1, לא ללוג
- הלוג של השער מצנזר טלפונים וגופי הודעות (`utils/logger.ts`)
- ההיסטוריה יושבת ב-SQLite של השער, לא בכספת ולא ב-D1
- שמירה קצרה: גוף ההודעה נמחק אחרי 24 שעות, השורה עצמה אחרי 30 יום
- ה-API של השער **לעולם אינו מחזיר** גוף הודעה או מספר טלפון, גם לא למנהל

הרקע, ולמה אין דרך אחרת:

הארכיטקטורה שביקשת הייתה `Browser → Worker → Gateway → WhatsApp`. היא לא
יכולה לעבוד כמו שהיא: `tzayad` מוצפנת מקצה לקצה ול-Worker אין מפתח פרטי. הוא
מאחסן בלוקים אטומים ולא יודע לפענח אף אחד מהם, ולכן **אינו יודע את מספר
הטלפון של החייל ואינו יכול לחבר "שלום דניאל, הבקשה שלך התקבלה"** — שני
הדברים האלה קיימים רק בדפדפן של המנהל, אחרי שהזין סיסמה.

הצורה שעובדת, וזו שמומשה:

```
Browser  (מפענח, מחבר את ההודעה)
   ↓     HTTPS + עוגיית הסשן הקיימת
Worker   (מאמת שזה מנהל, חותם HMAC, לא מאחסן)
   ↓     HTTPS + X-Signature
Gateway  (תור, הגבלת קצב, שליחה)
   ↓
WhatsApp
```

הדפדפן אינו מחזיק את סוד השער — הדרישה בסעיף 15 נשמרת. אבל **הטקסט הגלוי
ומספר הטלפון עוברים דרך השרת**, וזו הקלה מודעת. זה נכון לכל שער WhatsApp
שהוא: אי אפשר לשלוח הודעה בלי שהטקסט שלה ייצא מהמכשיר.

**`wa.me` הקיים לא נגעתי בו.** `waLink()`, `returnWaLink()` וכל העוגנים עם
`data-act="wa-sign"` / `wa-ret` נשארו בדיוק כפי שהיו — הם עדיין פותחים צ'אט
מהמכשיר של המנהל, בלי שאף פרט עובר בשרת. השער הוא תוספת: אם הוא כבוי, לא
מוגדר או מנותק, הקונסולה עובדת בדיוק כמו קודם.

| `src/db/index.ts` | SQLite + WAL + מיגרציות |
| `src/repositories/` | messages (תור והיסטוריה), idempotency, events, numbers |

| `src/services/queue/` | עובד יחיד, ריטריי אקספוננציאלי, שני חלונות קצב והשהיה אקראית |
| `src/services/messaging/templates.ts` | חמש תבניות בעברית, כולן חתומות "— מסייעת 951" |
| `src/middleware/` | חתימת HMAC, טיפול שגיאות, הגבלת קצב, IP allowlist |
| `src/routes/` | status, qr, connect, reconnect, logout, events (SSE), messages, check-number, health |
| `src/server.ts` | Express, תחזוקה תקופתית, כיבוי מסודר |
| `Dockerfile`, `docker-compose.yml` | תמונה עם Chromium, volume מתמיד, healthcheck |

בצד קלאודפלייר: נתיבי `/api/admin/wa/*` ב-`functions/api/[[path]].js` (רשימה
סגורה של שבעה נתיבים, לא מעבר נתיבים חופשי), ומסך **"וואטסאפ"** בקונסולת
המנהל — מצב החיבור, קוד ה-QR, התור, הודעת בדיקה, היסטוריה ויומן חיבור.

## הפעלה

### 1. השרת

צריך מכונה שרצה כל הזמן ויכולה להריץ דפדפן: VPS קטן, Raspberry Pi, כל דבר
עם 1GB זיכרון פנוי. **לא** קלאודפלייר.

```bash
cd gateway
cp .env.example .env
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"   # → API_SECRET
docker compose up -d
docker compose logs -f
```

### 2. קלאודפלייר

בהגדרות הפרויקט ב-Cloudflare Pages, שני משתני סביבה:

| שם | ערך |
|---|---|
| `WA_GATEWAY_URL` | הכתובת הציבורית של השער, למשל `https://wa.example.com` |
| `WA_GATEWAY_SECRET` | אותו `API_SECRET` בדיוק |

בלעדיהם המסך אומר "אינו מוגדר" והקונסולה ממשיכה כרגיל. זה מצב תקין.

### 3. הקישור

קונסולה → **וואטסאפ** → **חיבור**. תוך כמה עשרות שניות יופיע QR. בטלפון של
הקו: וואטסאפ ← הגדרות ← מכשירים מקושרים ← קישור מכשיר. הקוד מתחלף לבד והמסך
מתעדכן לבד. אחרי הסריקה המצב הופך ל"מחובר", ואז **הודעת בדיקה** למספר שלכם.

### 4. אחרי הפעלה מחדש

השער חוזר לבד — הסשן שמור ב-volume. סריקה חוזרת נדרשת רק אם ניתקתם ידנית, אם
ביטלתם את הקישור מהטלפון, או אם ה-volume נמחק.

## אזהרה שצריכה להיאמר

`whatsapp-web.js` הוא אוטומציה לא רשמית של WhatsApp Web. היא **מנוגדת לתנאי
השימוש של WhatsApp**, וחשבון ששולח דרכה יכול להיחסם — לפעמים לצמיתות, בלי
הודעה מראש ובלי ערעור. הסיכון אמיתי גם כשכל ההודעות לגיטימיות, וגדל עם הקצב.

לכן ברירות המחדל שמרניות בכוונה: 12 הודעות לדקה, לכל היותר אחת לשנייה, השהיה
אקראית של 3–9 שניות בין הודעות, עובד אחד. אל תעלו אותן בלי סיבה.

**אל תשתמשו במספר האישי שלכם.** קו ייעודי, שאם ייחסם לא ייקח איתו שום דבר אחר.

השער נועד להודעות שירות לחיילי המסייעת בלבד — אישור רישום, בקשת החזרה,
תזכורת. לא דיוור, לא רשימות תפוצה, לא איסוף מספרים. חמש התבניות ב-
`templates.ts` הן הרשימה הסגורה של מה שהוא מוכן לשלוח.
